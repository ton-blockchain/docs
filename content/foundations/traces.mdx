---
title: "Traces"
---

A _trace_ is a partially ordered set of messages according to the causal relation: "`A` is sent as a result of processing `B`". This set includes all dependent messages and related transactions. A trace can span several accounts and blocks.

In other words, if message `B` was sent while message `A` was being processed, then both of these messages belong to exactly **one** trace.

## Start of the trace

Most traces begin with an [external-in message](/foundations/messages/external-in) to a wallet contract, triggering a wallet transaction.

/>

[Tick-tock transactions](/foundations/messages/overview#transactions) can also start traces. These [election system-triggered](/foundations/system#elector) events do not have an incoming message.

<Callout type="note">
  In explorers, traces that start with a tick-tock transaction are often marked as initiated by the blockchain protocol.
</Callout>

## Logical time

Transactions and messages in a trace are ordered by [logical time (or `lt`)](/foundations/whitepapers/tblkch#1-4-1-logical-time), a non-negative 64-bit integer representing each event in a logically-dependent event sequence. The first event in a trace has the smallest `lt` value.

<Callout type="note">
  Logical time is **not** the elapsed wall-clock time.
</Callout>

A transaction receiving an internal message has a logical time greater than that message's creation time, and less than the logical times of its outgoing messages.

A receiving transaction's `lt` is not necessarily the incoming message's `lt` plus one: account history and the block's logical-time constraints also affect its assignment.

<Image

  darkSrc="/images/rpc/traces_lt_dark.png"
  alt="Example logical-time assignments along the branches of a trace"
/>

<Callout type="tip">
  The [first produced masterchain block](https://actonscan.com/block/-1/8000000000000000/1?network=mainnet) has the `lt` of `1,000,000`.
</Callout>

## Representation in explorers

Explorers visualize traces as [directed acyclic graphs (DAGs)](https://en.wikipedia.org/wiki/Directed_acyclic_graph), showing the full sequence of account state changes. Transactions appear as _nodes_ associated with accounts, and messages connect them as _edges_. The same account can have several transactions in one trace.

<Image
  src="/images/rpc/nft_transfer_trace_light.png"
  darkSrc="/images/rpc/nft_transfer_trace_dark.png"
  alt="NFT transfer trace"
/>

Explorers may display a partial trace if some messages or related transactions are unavailable or currently inaccessible from the [indexer](/api/v3/overview).

<Callout type="caution">
  Successful execution of an individual transaction in a trace does not by itself establish the success of the whole operation. Higher-level summaries given by explorers are interpretations of the trace data.
</Callout>

## Access using API

Use the [`GET /traces`](/api/v3/actions-and-traces/get-traces) endpoint to retrieve traces. It can filter and locate traces by related accounts or time ranges.
