The Open Network (TON) combines a blockchain with a peer-to-peer network and services for naming, file storage, web access, and off-chain payments. Applications can use these components together or select the ones they need.

Smart contracts manage on-chain state and enforce contract rules. Files, HTTP requests, and application processing can remain off-chain. For example, a website can serve its content over the TON network, use an on-chain domain record, and accept payments through payment channels.

## TON Network

The TON network carries communication between blockchain nodes and supports services beyond the blockchain.

The [Abstract Datagram Network Layer (ADNL)](/foundations/network/adnl) identifies peers by cryptographic addresses and provides encrypted communication. The [distributed hash table (DHT)](/foundations/network/dht) helps locate peers and discover nodes participating in services such as TON Storage.

These networking components let applications exchange data without recording each exchange as a blockchain transaction.

## TON DNS

[TON DNS](/foundations/web3/ton-dns) associates human-readable domain names with addresses and services. Records stored in smart contracts can identify payment recipients, TON Sites, files on TON Storage, or another resolver responsible for subdomains.

A domain such as `example.ton` can have several records for different purposes. Applications request the record they need, then use the returned address or content identifier to access the destination.

## TON Storage

[TON Storage](/foundations/web3/ton-storage) distributes files between peers. Files are grouped into a bag, identified by a BagID, which allows recipients to verify the downloaded content. The files remain on peers' disks.

Sharing files does not require an on-chain transaction. Optional storage contracts let clients pay providers to retain data and submit storage proofs. File availability still depends on peers retaining and serving the content.

## TON Proxy

[TON Proxy](/foundations/web3/ton-proxy) connects HTTP clients and servers through the TON network.

A forward proxy accepts requests from a browser or another HTTP client and sends them over the Reliable Large Datagram Protocol (RLDP), which runs over ADNL. A reverse proxy receives these requests and forwards them to an HTTP server.

Compatible forward proxies also provide access to files on TON Storage.

## TON Tunnel

[TON Tunnel](/foundations/web3/ton-tunnel) routes ADNL traffic through intermediate nodes. Applications with tunnel support can use relays instead of communicating directly from their own network endpoints.

Relays can forward traffic for free or charge through TON Payment Network. Tunnel routing applies to the traffic sent through the application's integration.

## TON Sites

[TON Sites](/foundations/web3/ton-sites) are websites and HTTP applications accessible through the TON network. They can be published in two ways:

- Connect an HTTP server through a reverse proxy to serve static files or dynamically generated responses.
- Publish static files as a bag on TON Storage.

TON DNS can associate a domain with either the reverse proxy's ADNL address or the storage BagID. Visitors access the site through a compatible client or a browser configured with a forward proxy.

## TON Payments

[TON Payment Network](/foundations/web3/payment-network) supports off-chain payments through interconnected payment channels.

Participants fund channels on-chain, then exchange signed state updates without submitting each payment to the blockchain. Smart contracts provide settlement and dispute procedures. Payments can also pass through intermediate nodes when a route has sufficient capacity.

Applications can use these channels for repeated small payments, including payments to TON Tunnel relays.
