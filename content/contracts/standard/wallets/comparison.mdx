[Unlike some other blockchains](/from-ethereum), wallets in TON are regular smart contracts. Each version defines its message format, replay protection, and optional features. For instance, [Wallet V5](/contracts/standard/wallets/v5) supports [gasless transfers](/contracts/standard/wallets/gasless), while [Highload Wallet v3](/contracts/standard/wallets/highload/overview) supports frequent batch transfers.

## Use cases

### Retail users

Most wallet apps use [Wallet V5R1](/contracts/standard/wallets/v5) by default when creating wallet accounts, while Telegram uses [WalletTg](/contracts/standard/wallets/telegram/overview). Other wallet apps need to support Telegram's wallet request format and key-management rules to import and operate the account.

<Callout type="note">
  When starting in the TON ecosystem, use either Telegram Money or a modern wallet app that supports both Wallet V5 and WalletTg contracts.
</Callout>

**Use for:**

- **Buying stablecoins:** Purchase USDT and other stable assets.
- **Trading jettons:** Swap tokens on decentralized exchanges and participate in decentralized finance (DeFi).
- **Daily payments:** Send and receive Gram and jettons.
- **NFT collecting:** Buy, sell, store, and transfer [non-fungible tokens (NFTs)](/contracts/standard/tokens/nft/overview).
- **Staking:** Stake Gram through a staking service and earn rewards.
- **dApp interactions:** Connect to games, social apps, and other decentralized applications (dApps) through [TON Connect](/applications/ton-connect/overview).
- **Savings:** Hold TON-based assets for long-term storage.

### Shared custody

Multisig contracts distribute transaction approval across key holders. In a threshold design, an order executes after it collects the configured number of signatures.

Multisig contracts are best for managing institutional funds, treasury assets, or any situation requiring shared custody.

**Key benefits:**

- **Shared responsibility:** A threshold above one can prevent a single signer from authorizing a transfer if the contract has no alternate authorization path.
- **Configurable thresholds:** Use a threshold such as 2-of-3 when the implementation supports it.
- **Auditability:** Pending orders and approvals may be recorded on-chain; visibility depends on the implementation.
- **Reduced single-key risk:** A threshold can remain usable after key loss if enough signers remain, but does not prevent collusion or every operational mistake.

Use multisig for team treasuries, shared budgets, and other spending that requires approvals from multiple key holders.

**Key considerations:**

- Additional signatures can increase message size, verification work, and fees.
- Signers must coordinate; a request may expire before it collects enough approvals.
- Setup, key management, signer changes, request limits, and recovery depend on the implementation.

### Payment gateways

[Highload v3](/contracts/standard/wallets/highload/overview) uses unique [`query_id`](/contracts/standard/wallets/highload/v3/specification#query-id-structure) values instead of a sequential [`seqno`](/contracts/standard/wallets/how-it-works#how-replay-protection-works), which allows clients to track multiple submitted requests without waiting for a single counter to advance. The query-ID format provides 8,380,416 possible values. Reuse follows the contract's timeout and replay-protection rules.

Batch transfers send an internal message to the wallet itself. That message can include up to 254 outgoing messages. These contract limits do not guarantee network throughput.

**Use for:**

- **Cryptocurrency exchanges:** Process withdrawals and payouts.
- **Payment processors:** Send merchant payments at higher volumes.
- **Trading platforms:** Submit many independent outbound transfers.

**Key considerations:**

- Budget for fees and balance consumed across the two-transaction pattern.
- Track unique query IDs, expiry, cleanup, and request outcomes.
- Keep request batches within the 254-message limit and test failure handling.

<Callout type="caution">
  Use Highload v3 for new deployments — previous highload wallet versions are deprecated.
</Callout>
