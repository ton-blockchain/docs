This guide shows how to send a single transfer from your Highload Wallet v3.

## Objective

By the end of this guide, you will:

- Send a single GRAM transfer from your Highload Wallet v3
- Understand how `query_id`, `created_at`, and [send modes](/foundations/messages/modes) work

## Prerequisites

- Completed [wallet creation](/contracts/standard/wallets/highload/v3/create) with funded balance and saved configuration in `.wallet.json`
- Use the Node.js project and wrapper files created in that guide. Create `wallet-send-single.ts` and append each TypeScript block below in order.
- For an authenticated TON Center endpoint, inject `TONCENTER_API_KEY` from protected storage.

## Step 2: Prepare the transfer message

Set `TON_TESTNET_RECIPIENT` to a valid testnet address and define the transfer inputs:

```typescript
// Not runnable: append to wallet-send-single.ts after the configuration block.
const recipient = process.env.TON_TESTNET_RECIPIENT;
if (!recipient) throw new Error('Set TON_TESTNET_RECIPIENT to a testnet address.');

const transferValue = toNano('0.01');
```

<Callout type="caution">
  **No state-init support:** Highload Wallet v3 cannot send messages containing [`StateInit`](/foundations/messages/deploy) using this method.

  If you need to deploy a contract (send a message with `StateInit`), use [batch transfers](/contracts/standard/wallets/highload/v3/send-batch-transfers) with an action list instead. The [limitations and constraints](/contracts/standard/wallets/highload/v3/specification#limitations-and-constraints) reference describes the supported messages.
</Callout>

## Step 3: Send the transfer

Send the transfer using the `sendExternalMessage` method:

```typescript
// Not runnable: append to wallet-send-single.ts after the transfer-message block.
// Reuse a saved request only when its stable ID and complete payload match.
function getOrReserveRequest(requestId: string, request: Record<string, unknown>) {
    const lockFd = fs.openSync('.wallet.json.lock', 'wx', 0o600);
    try {
        const current = JSON.parse(fs.readFileSync('.wallet.json', 'utf-8'));
        current.requests ??= [];
        const saved = current.requests.find((entry: any) => entry.requestId === requestId);
        if (saved) {
            if (JSON.stringify(saved.request) !== JSON.stringify(request)) {
                throw new Error('TON_REQUEST_ID already belongs to a different payload.');
            }
            const timeout = Number(request.timeout);
            if (!Number.isSafeInteger(saved.createdAt) || saved.createdAt + timeout <= Math.floor(Date.now() / 1000)) {
                throw new Error('Saved request is too old to retry by the local clock. Check its on-chain outcome before assigning a new ID.');
            }
            const queryId = HighloadQueryId.fromSeqno(BigInt(saved.seqno));
            if (queryId.getQueryId().toString() !== saved.queryId) {
                throw new Error('Saved query ID does not match its sequence number.');
            }
            return { request: saved.request, queryId, createdAt: saved.createdAt };
        }

        if (!Number.isSafeInteger(current.nextQuerySeqno) || current.nextQuerySeqno < 0) {
            throw new Error('Invalid nextQuerySeqno in .wallet.json.');
        }

        const queryId = HighloadQueryId.fromSeqno(BigInt(current.nextQuerySeqno));
        if (!queryId.hasNext()) throw new Error('Highload query ID space is exhausted.');

        const createdAt = Math.floor(Date.now() / 1000) - 30;
        const nextQueryId = queryId.getNext();
        current.nextQuerySeqno = Number(nextQueryId.toSeqno());
        current.requests.push({
            requestId,
            queryId: queryId.getQueryId().toString(),
            seqno: queryId.toSeqno().toString(),
            createdAt,
            request,
        });
        fs.writeFileSync('.wallet.json.tmp', JSON.stringify(current, null, 2), { mode: 0o600 });
        fs.renameSync('.wallet.json.tmp', '.wallet.json');
        return { request, queryId, createdAt };
    } finally {
        fs.closeSync(lockFd);
        fs.unlinkSync('.wallet.json.lock');
    }
}

const requestId = process.env.TON_REQUEST_ID?.trim();
if (!requestId) throw new Error('Set TON_REQUEST_ID to a stable ID for this intended transfer.');
const request = {
    kind: 'single',
    recipient: Address.parse(recipient).toRawString(),
    valueNano: transferValue.toString(),
    bounce: false,
    body: 'empty',
    mode: SendMode.PAY_GAS_SEPARATELY,
    subwalletId: walletData.subwalletId,
    timeout: walletData.timeout,
};
const saved = getOrReserveRequest(requestId, request);
const savedRequest = saved.request;
const internalMessage = internal({
    to: Address.parse(String(savedRequest.recipient)),
    value: BigInt(String(savedRequest.valueNano)),
    bounce: Boolean(savedRequest.bounce),
});

await wallet.sendExternalMessage(keyPair.secretKey, {
    message: internalMessage,
    mode: Number(savedRequest.mode),
    query_id: saved.queryId,
    createdAt: saved.createdAt,
    subwalletId: Number(savedRequest.subwalletId),
    timeout: Number(savedRequest.timeout),
});

console.log('Transfer sent');
console.log(`Query ID: ${saved.queryId.getQueryId()}`);
console.log(`Created at: ${saved.createdAt}`);
```

`TON_REQUEST_ID` identifies one intended transfer. If submission is uncertain, rerun the command with the same ID and inputs. A retry reuses the saved query ID, timestamp, and payload; changed inputs fail.

Once the saved timestamp is at least `timeout` seconds old by the local clock, the script stops retries. Before replacing the request, wait for a confirmed block in the wallet's shard with a timestamp at or beyond `createdAt + timeout`. Check the wallet and recipient histories and resolve pending outgoing messages. Use a new `TON_REQUEST_ID` for a replacement only after confirming the transfer did not execute.

The exclusive lock serializes reservations across processes. Remove a stale lock only after confirming that no sender process is running. For a service with many requests, use a transactional database for the allocator and outbox.

In a private shell, inject the mnemonic without putting it in shell history, set a testnet recipient and stable request ID, then run the script:

```bash

```

<Callout type="note">
  **Automatic deployment:** If your wallet is in `uninit` status (has a balance but no code), this external message deploys it and sends the transfer directly. Deployment and transfer happen in the same transaction.
</Callout>

### Parameter explanation

**`query_id`** — Unique identifier for replay protection:

- Each `query_id` can only be processed once within the protection window
- `HighloadQueryId` is a wrapper class that represents the composite `query_id` as a sequential counter
- `getNext()` returns a new wrapper object; it does not mutate the current one
- Total range: 8,380,416 unique IDs
- The [query ID structure](/contracts/standard/wallets/highload/v3/specification#query-id-structure) reference defines the counter layout

**`createdAt`** — Message timestamp for expiration:

- Set to 30 seconds **before** current time: `Math.floor(Date.now() / 1000) - 30`
- Compensates for blockchain time lag (lite-servers use last block time, not current time)
- The [timestamp validation](/contracts/standard/wallets/highload/v3/specification#timestamp-validation) rules explain this offset

## Next steps

Your wallet is ready to send transfers. Use an atomic shared allocator before sending requests in parallel.

To verify a direct transfer, find the wallet's external transaction by its saved `queryId` and `createdAt`. Confirm that its VM compute and action phases succeeded, then compare the outgoing message with the saved recipient, value, and bounce flag. This example uses an empty body. Check the recipient's transaction history to confirm downstream execution. This method sends directly from the external transaction; it has no self-message transaction. The [batch verification guide](/contracts/standard/wallets/highload/v3/verify-is-processed) covers only the two-transaction batch flow.
